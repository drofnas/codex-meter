# Security

## Reporting a vulnerability

Use the repository's **Security → Report a vulnerability** option when it is
available. If private reporting is unavailable, open an issue asking the
maintainer to enable it without including exploit details or sensitive data.
Never attach credentials, account responses, personal usage history, serial
captures, or locally compiled firmware to a public report.

## Supported deployment

This is a personal meter for a trusted private LAN. The device uses plaintext
HTTP, so anyone able to intercept that traffic can read the dedicated meter
token and usage data. The token grants read access to usage and retained history.
Use a separate token generated by the installer, restrict access to your trusted
network, and do not expose the API through port forwarding or a public tunnel.
Remote or shared-network deployment requires authenticated encrypted transport.

The native collector reads Codex credentials locally and sends them only to the
fixed HTTPS usage endpoints. It disables redirects and proxies and does not
refresh credentials or redeem resets. The API container receives only the
prepared usage directory and a separate meter token. It has no Codex credential
mount. The upstream usage endpoint is an internal compatibility dependency and
can change independently of this project.

## Private files and release artifacts

- Keep `secrets.yaml`, `.env` files, `.local/`, `.esphome/`, and `artifacts/` private.
- Firmware binaries contain the configured Wi-Fi credentials and meter token.
  Build them locally; never upload a personal build as a release asset.
- Usage snapshots, serial captures, screenshots, and deployment notes can reveal
  personal activity even when they contain no authentication secrets.
- Use synthetic observations in tests and examples. Do not copy account IDs,
  real observation/reset timestamps, or personal home-directory paths into source.
- Run the [publication checks](CONTRIBUTING.md#publication-checks) before pushing.
  Ignore rules do not protect files that are already tracked or force-added.

If a credential is published, revoke or rotate it with its issuing service and
remove it from repository history. Deleting the current file alone does not
remove previous versions.

## Toolchain maintenance

Use Go 1.26.8 or a newer patched release. The module minimum enforces that floor;
the API's Docker build pins its own compiler image. Rebuild the native collector
after updating Go, following the installation guide's stop/install/start flow.
Keep Python and Docker updated as well.

The pinned ESPHome build dependency requires PlatformIO 6.1.19, whose
`starlette<0.53` constraint retains known Starlette advisories, including
[GHSA-82w8-qh3p-5jfq](https://github.com/Kludex/starlette/security/advisories/GHSA-82w8-qh3p-5jfq).
ESPHome 2026.8.2 also retains that PlatformIO pin. Use an isolated build environment
and the CLI build path; do not run PlatformIO's web service with this environment.
A compatible upstream dependency update is required to clear these advisories.
Do not force an incompatible Starlette override. Python build tooling is not
included in the native collector or API runtime.
